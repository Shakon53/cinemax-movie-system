# Подтверждение регистрации: исправление 19 октября 2026

Проверка реального `/auth/v1/verify` с заведомо недействительным диагностическим токеном установила причину: сервер возвращает HTTP 303 на `http://localhost:3000`. Это происходит как без `redirect_to`, так и с адресами опубликованного сайта `/auth.html` и `/auth`. Пользовательская регистрация в журнале Auth возвращала 200, проверка ссылки — 303. Данные пользователя и действительные токены для диагностики не использовались.

## Обязательная настройка облака

Открыть [Authentication → URL Configuration](https://supabase.com/dashboard/project/gvifasloexjfhzdokgoq/auth/url-configuration):

- Site URL: `https://willowy-treacle-e1845e.netlify.app`
- Redirect URLs: добавить и сохранить все четыре адреса:
  - `https://willowy-treacle-e1845e.netlify.app/auth.html`
  - `https://willowy-treacle-e1845e.netlify.app/auth`
  - `https://willowy-treacle-e1845e.netlify.app/reset.html`
  - `https://willowy-treacle-e1845e.netlify.app/reset`

HTML и адрес без расширения нужны из-за обработки URL в Netlify. Подключённый Supabase MCP не предоставляет изменение Auth configuration, доступного браузера нет. На момент подготовки этого документа настройка запрошена у владельца; успешное изменение не подтверждено. Публикация frontend сама по себе этот адрес Supabase не меняет.

## Изменения сайта

- Ошибки `otp_expired` и другие ошибки возврата из письма показываются на странице входа; авторизация и подтверждение не выдумываются.
- Доступна повторная отправка существующего подтверждения через `auth.resend({type:'signup',...})`. Письмо отправляется только при нажатии пользователем, с ограничениями Supabase.
- После регистрации сохраняется email в форме входа, показывается инструкция и кнопка повторной отправки.
- Успешный возврат ждёт получения реального пользователя через Supabase; переход после ручного входа учитывает безопасный `returnTo`.
- Ссылка восстановления, попавшая на страницу входа, передаётся на `reset.html` с исходным фрагментом. Подтверждение email остаётся включённым.

Проверено 27 локальными тестами, включая успешный и просроченный callback, повторную отправку и безопасный адрес возврата. Настоящее письмо и вход по нему не проверены: требуется исправленная облачная конфигурация и пользовательская почта. После изменения настроек повторить `.tools/check-auth-redirect.mjs`: результаты должны указывать на опубликованный сайт, а не localhost. Затем пользователь может открыть старое письмо либо запросить новое, если ссылка уже истекла.

Документация Supabase: [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls), [Resend confirmation](https://supabase.com/docs/reference/javascript/auth-resend).
