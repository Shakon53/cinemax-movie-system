### Добавленные возможности без смены интерфейса

- Главная: раскройте «Подобрать по настроению и времени» под жанрами. Доступны настроение, длительность, насыщенность, бесплатные фильмы и случайный выбор с учётом фильтров.

Участник должен сохранить открытой свою вкладку либо вернуться в неё: ключ участника хранится в sessionStorage, а не в пригласительной ссылке.
- Отзывы: автор отмечает наличие спойлеров; текст скрыт до раскрытия. Автоматический ИИ-анализ не добавлен.
- Админка: настроение, метки, насыщенность и публикация/черновик для фильма.
- Проверки: 14 локальных тестов проходят. Реальные запросы Supabase проверили каталог, метки, связи карточки, защиту старых аккаунтов и совпадение двух участников. Один аккаунт создан через регистрацию; email пока не подтверждён. Полный вход и восстановление пароля не подтверждены. Визуальная проверка в браузере пока недоступна — подключённого браузера нет.

Для нового пустого проекта порядок: 001 → seed → 003 → 004; файл 002 предназначен только для переноса существующих таблиц .NET и на пустой базе не запускается. ## Что подготовлено

Frontend работает напрямую с Supabase Auth и Data API. Отдельный .NET-сервер для этого режима не нужен.
Старый ASP.NET-проект сохранён как альтернативный вариант; он не используется при CINEMAX_BACKEND = 'supabase'.

- Регистрация, подтверждение email, вход, выход и восстановление пароля.
- Каталог, поиск, жанры, сортировка, страницы фильмов/актёров/режиссёров.
- Отзывы от имени вошедшего пользователя, избранное аккаунта между устройствами.
- Гостевое избранное отдельно в браузере; оно не переносится автоматически в чужой аккаунт.
- Управление каталогом и пользователями через админку с проверкой прав в PostgreSQL.
- 10 исходных карточек фильмов плюс Big Buck Bunny и Sintel с атрибуцией и официальными ссылками.
- Бакет posters для изображений до 5 МБ, запись разрешена только администраторам. Пока изображения добавляются через Supabase Storage, а URL вставляется в админке.

Видео на Supabase Storage не загружаются. Для коммерческих фильмов есть только описание/трейлер, без обещания бесплатного просмотра.

## 1. Создать Supabase

В https://supabase.com/dashboard создайте новый проект. Пароль базы задавайте в интерфейсе Supabase; для frontend он не нужен.
Дождитесь готовности проекта. Для нового проекта выполните в SQL Editor по порядку:

1. supabase/migrations/202610150001_cinemax.sql
2. supabase/seed.sql
3. supabase/migrations/202610150003_vibes_match.sql
4. supabase/migrations/202610150004_initial_admin.sql

Файл 202610150002_preserve_legacy.sql нужен только при переносе старых таблиц .NET; на новом пустом проекте он пропускается. Для существующего проекта gvifasloexjfhzdokgoq перечисленные миграции уже применены, повторять их не нужно.

Миграция создаёт новые таблицы и политики. Если в проекте уже есть таблицы с такими именами, сначала проверьте их и сделайте резервную копию. Миграция не удаляет существующие таблицы; при конфликте операция отменяется.
Seed можно запустить повторно: существующие строки с теми же ID не перезаписываются.
Это начальный каталог из локального шаблона, а не выгрузка старой облачной базы. Существующие аккаунты и пароли из старого API автоматически не переносятся.

## 2. Подключить frontend

В Connect / Project Settings возьмите Project URL и публичный Publishable key (поддерживается и legacy anon key).
Заполните Frontend/js/config.js:

```js
window.CINEMAX_BACKEND = 'supabase';
window.CINEMAX_SUPABASE = {
  url: 'https://YOUR_PROJECT.supabase.co',
  publishableKey: 'sb_publishable_...'
};
```

В этом файле допустим только публичный ключ. secret/service_role и пароль PostgreSQL туда не вставляйте.
Доступ к данным ограничивают RLS-политики, а не скрытность публичного ключа.

## 3. Почта и адреса Auth

Authentication → URL Configuration:

- Site URL: фактический адрес сайта, пока https://willowy-treacle-e1845e.netlify.app
- Redirect URLs: https://willowy-treacle-e1845e.netlify.app/auth.html и https://willowy-treacle-e1845e.netlify.app/reset.html
- Для локальной проверки добавьте http://localhost:8080/auth.html и http://localhost:8080/reset.html.

Включите Email provider и подтверждение email; задайте минимальную длину пароля 10 символов.
Для регистрации публичных посетителей подключите Custom SMTP в Authentication. Встроенная почта Supabase отправляет сообщения только адресам членов команды проекта и имеет низкие лимиты.
Руководство: https://supabase.com/docs/guides/auth/auth-smtp
Секрет SMTP задаётся только в панели Supabase.

Проверьте подтверждение email и восстановление пароля до приглашения посетителей.

## 4. Назначить администратора

Сначала зарегистрируйтесь на сайте и подтвердите email. В SQL Editor выполните, подставив свой адрес:

```sql
insert into public.user_roles(user_id, role)
select id, 'admin' from auth.users where lower(email) = lower('YOUR_EMAIL')
on conflict (user_id) do update set role = excluded.role;
```

Проверьте, что назначена ровно одна нужная учётная запись. Войдите через /login.html.
Роль из браузерного localStorage или signup metadata не даёт прав администратора.
SQL Editor выполняет владелец проекта; public/anon key не может назначить администратора.

## 5. Обновить существующий сайт Netlify

После заполнения config.js откройте в Netlify проект willowy-treacle-e1845e → Deploys и загрузите папку Frontend в область ручного развёртывания.
Не загружайте весь репозиторий: публичной папкой является только Frontend.
При автоматическом деплое publish directory — Frontend, сборка не требуется; netlify.toml уже настроен.
Не публикуйте новую версию с пустым config.js: она покажет ошибку подключения.

## 6. Бесплатный адрес cinemax-….netlify.app

В Netlify откройте проект → Project configuration → General → Project details → Project information → Manage project name and cover image.
Задайте, например, cinemax-movies-kz. Если имя занято, выберите другой суффикс.
Netlify покажет новый адрес вида https://cinemax-movies-kz.netlify.app; доступность имени заранее не проверялась.

После изменения имени обновите в Supabase Site URL и обе Redirect URLs на фактический новый адрес. Новые письма подтверждения и восстановления должны вести на новый сайт.
Само изменение имени проекта Supabase адрес сайта не меняет. Платный Supabase Custom Domain для этой схемы не нужен.

Документация Netlify: https://docs.netlify.com/resources/troubleshooting/overview/#help-changing-project-name
