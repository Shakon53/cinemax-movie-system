# CineMax на AWS EC2

## Текущее состояние

Сайт использует ASP.NET Core 8 и PostgreSQL (исходный README с MSSQL устарел).
Подготовлен запуск трёх контейнеров: сайт/API, PostgreSQL и Caddy с HTTPS.
На AWS ничего не создано и не перенесено. CLI запущен локально, но без входа AWS возвращает NoCredentials.

## Восстановление доступа

PEM-файл — ключ SSH. Он не содержит IP сервера и не авторизует AWS API.
Официальный AWS CLI распакован в %LOCALAPPDATA%/CineMaxTools/aws-cli.
Из PowerShell в папке проекта:

~~~powershell
.\scripts\aws.ps1 login --region us-east-1
.\scripts\find-ec2.ps1
~~~

Первая команда открывает браузер для входа в AWS. Если вход не работает, восстановите пароль/доступ к MFA через официальный AWS sign-in. Пароли и MFA не отправляйте в чат.
Вторая команда только читает список EC2 во всех доступных регионах и показывает IP, состояние и имя ключа.
Ищите ключ lms-key. Имя файла может отличаться от имени пары ключей AWS.
Остановленный сервер может не иметь публичного IP; автоматически он не запускается.

## Развёртывание после восстановления доступа

1. Проверьте оставшиеся кредиты и срок Free Tier в Billing. Бесплатность зависит от возраста аккаунта и плана: https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-free-tier-usage.html
2. Подключитесь через SSH с ключом из Downloads к найденному IP. Для Ubuntu обычно используется ubuntu, для Amazon Linux — ec2-user.
3. Проверьте существующие сервисы и сделайте резервную копию перед изменениями. В проекте нет подключения к старому серверу или его базе.
4. Установите Docker Engine и Compose по официальной инструкции для ОС сервера. Маленькому EC2 может не хватить памяти для сборки .NET: собирайте образ вне сервера при необходимости.
5. Загрузите Frontend, MovieManagement.API, compose.yaml и deploy/Caddyfile. PEM-файл и локальные секреты не загружайте.
6. Привяжите собственный домен A-записью к IP. В Security Group откройте 80/443 для сайта; SSH 22 только со своего IP. PostgreSQL 5432 и API 8080 наружу не публикуются.
7. Скопируйте .env.example в .env на сервере. Задайте домен SITE_ADDRESS без протокола, свой ADMIN_EMAIL и случайные POSTGRES_PASSWORD/ADMIN_PASSWORD. Пароль администратора — минимум 16 символов. Для пароля БД удобно использовать результат openssl rand -hex 32.
8. Выполните docker compose config --quiet и docker compose up -d --build. Просмотрите docker compose logs --tail=100 app и откройте https://ВАШ-ДОМЕН/health.
9. Проверьте регистрацию, вход, отзыв от своего аккаунта, выход и запрет доступа обычного пользователя к админским API. Вход администратора: /login.html с ADMIN_EMAIL и ADMIN_PASSWORD. Старые пароли admin123 больше не работают.

Тома postgres_data и session_keys сохраняют базу и сессии при пересоздании контейнеров. Не выполняйте docker compose down -v: это удалит данные.
Резервная копия БД: docker compose exec -T db pg_dump -U cinemax -d cinemax -Fc > backup.dump. Копию храните отдельно от EC2.

## Изменения приложения

- Сессии в HttpOnly cookie, серверные права администратора, ограничение попыток входа.
- Новые пароли хешируются PasswordHasher с солью; старые SHA256 обновляются после верного входа. Аккаунты без пароля больше не захватываются первым входящим.
- Отзывы создаются от авторизованного пользователя; удаление — автором или администратором.
- Данные пользователей и управление каталогом доступны администраторам; хеши паролей удалены из ответа API.
- Frontend и API используют один адрес /api. Старые адреса Render больше не используются.
- /free.html: поиск двух открытых фильмов с лицензиями и переходом на официальные страницы. Встроенный просмотр и загрузка видео на AWS не добавлялись.

Лицензии: https://peach.blender.org/about/ и https://durian.blender.org/about/.

## Проверка

Проверка JavaScript выполняется локально. Полная сборка .NET, интеграция с PostgreSQL и Docker-развёртывание требуют SDK/Docker либо сервера; в текущей среде они отсутствуют. До этих проверок не считать конфигурацию проверенным production-развёртыванием.

Перед миграцией существующей базы проверьте повторяющиеся email/имена без учёта регистра: новые уникальные индексы остановят миграцию при дубликатах. Автоматически существующие пользователи не удаляются.
