# Обновление CineMax: дневник, статистика и подбор — 19 октября 2026

## Что подготовлено

- `profile.html`: личный дневник, «Хочу посмотреть» и «Просмотрено», оценка 1–10, приватная заметка и дата просмотра.
- На странице фильма три действия: хочу посмотреть, просмотрено, избранное. Заметка дневника не публикуется как отзыв.
- Статистика: число просмотров, частые жанры, лучшие личные оценки и просмотры по месяцам. Один фильм — одна запись; повторный просмотр редактирует её, отдельные сеансы не хранятся.
- Каталог сохраняет поиск, актёра, жанр, настроение, время и номер страницы в URL. При возврате браузером восстанавливается положение прокрутки.
- Поиск по имени актёра учитывает главную роль и таблицу актёрского состава; на странице актёров есть ссылки на их фильмы. Добавлены распространённые русские варианты нескольких имён.
- Find My Movie: описание настроения на русском/казахском, уточнение времени, строгий учёт длительности и исключение просмотренных фильмов при доступном дневнике. Пример: «Мен шаршадым, не хочу страшное» подбирает лёгкое спокойное кино.
- Подготовлено 22 новых карточки коммерческих фильмов и 2 дополнительных открытых фильма. После применения миграции на исходном каталоге ожидается 36 опубликованных фильмов, включая 4 с полным просмотром.
- Для Big Buck Bunny, Sintel, Elephants Dream и Tears of Steel указан официальный встроенный плеер Blender. Проверены ответы API и длительности полных версий; фактическое воспроизведение в браузере ещё не проверено.
- Для новых коммерческих карточек созданы собственные типографические обложки CineMax. Это не официальные постеры. Неизвестные оценки, биография актёров и страны не выдуманы; оценка каталога `0` означает отсутствие оценки.

Исходники и тесты подготовлены локально. На момент подготовки этого документа подключение Supabase в текущей сессии недоступно: новые миграции не применены к рабочему проекту. Поэтому нельзя считать новые личные списки, расширение каталога и ИИ уже работающими на опубликованном сайте.

До обновления production сначала примените изменения базы. Старые миграции `001`–`004` повторно не запускайте.

Владелец проекта `gvifasloexjfhzdokgoq` выполняет в SQL Editor по порядку:

1. [005 — дневник и источник полного просмотра](supabase/migrations/202610190005_movie_journey.sql).

Каждая миграция — отдельная транзакция. `005` и `007` не предназначены для повторного выполнения. `006` проверена на повторный запуск: карточки и связи не дублируются. Сделайте резервную копию перед изменением базы.

`movie_journey` защищена RLS: пользователь читает и изменяет только собственные строки, публичного доступа нет. Владелец проекта с административным доступом к базе технически может читать эти данные; приватность в интерфейсе не означает сквозное шифрование.

После миграций опубликуйте папку `Frontend` через существующий Netlify. Адрес сайта не меняется. Новые исходники сами по себе не меняют рабочую базу и не подтверждают успешный деплой.

## Настоящий ИИ: необязательное отдельное подключение

Без ключа внешней модели Find My Movie работает **по правилам**, не выдавая этот режим за генеративный ИИ. Он понимает предусмотренные выражения и уточняет настроение/время; произвольный диалог не обещается.

Серверная функция: [supabase/functions/movie-concierge/index.ts](supabase/functions/movie-concierge/index.ts). Она использует совместимый с Chat Completions API провайдер, проверяет Supabase JWT, ограничивает запросы и возвращает только ID из доступного каталога. Ключ модели никогда не попадает в frontend.

Для её включения:

1. Примените `007`.
2. Настройте секреты функции через доверенную панель Supabase: `AI_API_URL` — HTTPS-адрес Chat Completions endpoint; `AI_API_KEY` — секрет провайдера; `AI_MODEL` — имя модели; `SITE_URL` — фактический адрес сайта без завершающего `/`.
3. Разверните функцию `movie-concierge` с проверкой JWT. Стандартные `SUPABASE_URL` и `SUPABASE_ANON_KEY` берутся из окружения функции.
4. Только после успешной проверки установите `window.CINEMAX_AI_ENABLED = true` в `Frontend/js/config.js` и опубликуйте frontend.

Нужен вход в аккаунт. Ограничение: не чаще одного запроса в 15 секунд и до 20 запросов в сутки на аккаунт. Тариф и обработка запросов внешним провайдером зависят от выбранного сервиса. При сбое модели интерфейс явно переключается на подбор по правилам.

## Проверка после публикации

1. Войти двумя разными аккаунтами и убедиться, что их дневники раздельны.
2. Отметить просмотр, задать дату прошлого месяца и оценку; проверить статистику и приватность заметки.
3. Изменить статус, убрать запись; убедиться, что статистика пересчиталась.
4. Найти фильм по актёру, выбрать фильтры, открыть карточку и нажать «Назад»: фильтры, страница и прокрутка должны сохраниться.
5. Проверить запрос «я устал, не хочу страшное» и строгие интервалы времени. При отсутствии совпадений условия не ослабляются автоматически.
6. Открыть каждый из четырёх полных фильмов на настольном и мобильном браузере. Провайдер видео может быть недоступен в отдельных сетях; ссылка на официальную страницу остаётся запасным вариантом.
7. При подключении ИИ проверить вход, ограничение частоты, ответы модели и поведение при её недоступности.

Локально выполняйте `npm ci` и `npm test`. Проверки исполняют миграции в PostgreSQL через PGlite, проверяют RLS, статистику, фильтры, поиск актёров и защиту источников видео. Браузерная проверка остановилась: Computer Use не смог достоверно определить текущий адрес браузера.
